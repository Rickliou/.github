## Work Tracking

目標：任何時候都能回答「AI 正在做什麼、為什麼這樣改、怎麼知道完成」。

### 分工與決策邊界

- 人決定：需求價值、優先序、行為取捨、合併（另有明確授權時依授權）、實際環境操作的授權與驗收結果。
- AI 負責：調查現況、提出拆解與可驗證的驗收條件、實作、測試、文件、PR 與看板更新。
- 已授權範圍內的例行實作選擇自行決定。要改變需求、擴大範圍或新增未授權的外部影響時，先列出具體選項與影響請人決定；已有授權不重複詢問。
- 範圍外的問題另開 issue，不要併入當前工作。

### 開工

1. 每項工作都要有 issue；沒有就先用 `gh issue create` 開。issue 至少寫明（小改動每項一句話）：
   目的與預期行為、本次範圍與排除事項、可檢查的驗收條件（含必要的異常與安全情境）、
   依賴／基準分支／待決問題（無則寫「無」）、風險與實際驗收需求。
2. 開始前讀 issue、本檔與 Git 狀態，用幾句話重述理解與驗證方式後直接開始。只有會改變方向或需要新授權的問題才暫停相依工作，其餘可獨立進行的調查繼續做。
3. 依內容判斷是否補「高風險」「需實際驗收」label，不只看表單勾選或既有 label。
4. 分支名：`<type>/<issue 號>-<簡述>`，例如 `fix/12-null-weight`，從「專案設定」的正式整合分支開出。開分支時把卡片 Status 改成「進行中」。
5. 「進行中」同時最多 1～2 張。並行前確認修改範圍與相依關係；不讓多個 AI 同時修改同一工作目錄。

### PR 與證據

6. PR 依範本填寫。「驗收證據」表逐條對應 issue 的驗收條件：證據寫測試名稱／指令、CI 或結果連結；結果填通過、失敗、待驗收或不適用（須說明原因）。不能只寫「全部測試通過」。失敗或未執行的項目列在「未驗證事項」，不得勾成完成。
7. 單元測試、重播／模擬與現場驗收證明不同事情：呼叫上報函式不等於平台已收到資料；測試套件通過不能代替硬體驗收。
8. 「高風險」的改動，合併前跑「專案設定」的回歸驗證。先定義預期改變與必須維持的安全條件；新舊結果的每項差異都要能解釋，不一律要求完全相同，也不把所有差異當成合理。控制邏輯的變更保持範圍小，明列安全條件與異常路徑。
9. 部署前確認驗證對應的 SHA，不沿用舊版本的通過結果。
10. PR 的「對應 issue」：
    - 沒有「需實際驗收」：寫 `Closes #N`，合併後卡片自動到「完成」。
    - 有「需實際驗收」：寫 `Refs #N`。合併後把 Status 改成「等驗收」，並在 issue 留下「等驗收紀錄」。

### 等驗收與實際驗收

11. 等驗收紀錄（尚未部署就寫「未部署」；不記錄密鑰）：

    ```markdown
    ### 等驗收紀錄
    - PR／合併 commit SHA：
    - 部署 SHA（與合併 SHA 不同須說明）：
    - 站點／環境、部署時間、影響行為的設定差異：
    - 驗收步驟與通過條件：
    - 要觀察的異常；結果或 log 位置：
    - 回滾版本、操作方式與適用條件：
    - 驗收人／時間／結果／後續處置：待填
    ```

12. 「需實際驗收」的 issue 由人判定並關閉，AI 不關。未通過時記錄失敗條件與下一步，Status 改回「進行中」。因部署或場次等待而停在「等驗收」時，在 issue 記錄原因與下一個可驗收時間。

### 中斷與接續

13. 工作階段結束或交接前，在 issue 留言：

    ```markdown
    ### 進度交接
    - 目前進度：
    - 分支／PR／最新 commit：
    - 已執行的驗證與結果：
    - 未完成事項：
    - 阻礙與待決問題：
    - 下一步：
    ```

14. 接手時先核對 issue、本檔、Git 狀態與實際差異再繼續；不能只依上次聊天摘要判定已完成。
15. 資訊放置：工作範圍、進度、待辦與驗收結果放 issue；實作與驗證證據放 PR，兩者互相連結；架構、操作方式與長期技術決策放 repo 文件或 ADR，issue／PR 連回去。commit body 保留決策理由與實測背景。

### 改卡片 Status 的指令

ID 見下方專案設定：

```bash
item=$(gh project item-add <Project 編號> --owner <OWNER> --url <issue 網址> --format json --jq .id)
gh project item-edit --id "$item" --project-id <Project ID> --field-id <Status 欄位 ID> --single-select-option-id <選項 ID>
```

- 高風險指的是：<碰到哪些模組、設定或條件>

- 實際驗收在哪裡做：<場域、實機、使用者試用>
